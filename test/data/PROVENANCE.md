# Test data

`cases/*.json` are mapping scenarios: an instruction, a context and the result the rules in the README give for it, written from an independent reading of those rules over the bundled documents, or over the inline documents a case carries. Each case is named for what it pins. A case whose note begins `Fixture-only:` carries an inline document modelled on a program no bundled document covers, and it pins a rule, not that program's mapping. A case that stops matching its document is a rule change, and the case moves with the rule.

`vectors/<environment>/<program>.json` are generated by `scripts/generation/ix-mapper-vectors.mjs`: for every entry of every bundled document, the result this package's mapper gives a canonical instruction under a fixed context, one vector per variant the entry admits (every position present, the omittable tail absent, the program-id optionals present, one account beyond the list, the supplied accounts served, the optional ones left out, unserved), and one instruction per document that no entry matches. They are this mapper's own output, so another mapper that replays them agrees with this one on every entry; they prove equivalence, not correctness, and never replace a case. The generator's `--check` refuses a stale file.
